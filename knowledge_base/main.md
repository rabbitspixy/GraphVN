# 🗺️ Карта контекста проекта (Context Map)

Этот файл является точкой входа для LLM-агента. Здесь описана структура базы знаний и назначение каждого документа.

## Суть проекта

Игровой движок для создания нелинейных текстовых квестов или визуальных новелл, с помощью редактирования графа состоящего из узлов и переходов между узлами.

## Сценарии проекта

### Режим проигрывания квеста

#### Описание UI
- Картинка на заднем фоне на весь экран.  
- Снизу отображается текст для чтения.  
- Над текстом присутствует имя персонажа, если укаазано  
- Кнопки переходов.  
- Сверху слева отображаются значения всех данных квеста, для отладки

#### Игровой флоу
- Игрок всегда находится в каком-то узле, и передвигается между узлами с помощью кнопок, запускающих переход между узлами.
- Игрок читает текст узла, смотрит картинку и дальше думает какую кнопку перехода нажать.
- Каждый переход между узлами и каждый вход в узел, может менять состояние данных квеста
- Переходы могут быть не всегда доступны, это определяется условием перехода
- Переходы могут быть без текста, тогда кнопок вообще не будет, игроку нужно будет просто нажать в любую часть экрана

### Флоу создания квеста

#### Страница редактирования графа, узлов и переходов
- Холст на котором отрисовывается граф
- Можно добавлять/удалять/перемещать узлы
- Можно добавлять/удалять переходы между узлами
- Справа от холста окошко редактирования выделенного узла или перехода

#### Страница редактирования данных квеста
- Добавление/Удаление/Редактирование структуры данных (Группировка переменных в одну папку)
- Добавление/Удаление/Редактирование переменных в структурах
- Добавление/Удаление/Редактирование типов именованных значений

### Логика квеста

#### Естественный язык для всех действий

**Игровая логика пишется полностью на естественном языке.** Весь текст трансформируется LLM моделью в JS код.

Пользователь заполняет специальные поля при редактировании узлов и переходов:
- **Действия** — что происходит при входе в узел или использовании перехода
- **Условия** — когда переход доступен или когда срабатывает триггер
- **Вставки** — динамическая подстановка текста в реплики и описания узлов

**Синтаксис вставок:** Текст заворачивается в символы `{{ ... }}`. При выполнении JS код генерирует строку, которую вставляет в указанное место.

#### Генерация кода

Кнопка «Сгенерировать код» находится на странице AI:
- Перепроверяет изменения во всём проекте
- Перезапускает генерацию JS кода только если что-то изменилось
- Генерирует код для всех действий, условий и вставок на естественном языке
- Сохраняет сгенерированный JS код внутрь проекта (недоступен для ручного редактирования)

Промпты генерации находятся в `js_code_generator.dart`. Текущий процесс:
1. Собирает контекст всех переменных проекта (из `variables.dart`)
2. Формирует промпт с описанием задачи на естественном языке
3. Отправляет в LLM модель
4. Извлекает JS код из блока ```javascript``` в ответе
5. Если ошибка — возвращает `null`, и генерация повторяется

#### Условия триггеры

Все условия из проекта собираются в единый список и проверяются каждые раз, когда меняется состояние квеста (после выполнения действий в переходах и узлах).

Отличие от обычных условий перехода:
- **Обычные условия перехода** — проверяются только при попытке перейти по кнопке
- **Условия триггеры** — проверяются автоматически при любом изменении состояния и могут перенести игрока без его действия

Условие триггер вписывается в текстовое поле `naturalLanguageTrigger` в узле. Если условие выполняется — игрок автоматически перемещается в этот узел.

#### Где редактируется код

- **Редактируется только описание на естественном языке** — в UI редактора при работе с узлами и переходами
- **JS код генерируется полностью LLM моделью** — сохраняется в проекте, недоступен для редактирования
- **Синтаксис вставок** — текст в узлах и переходах заворачивается в `{{ ... }}`, LLM генерирует JS для получения строки

#### Структура проекта

Проекты сохраняются в виде папки, в которой:
- **Бинарный файл protobuf** — основной файл проекта со всеми данными
- **Ассеты** — все картинки, изображения и ресурсы хранятся в той же папке

#### Страница запуска генерации кода
- На этой странице осуществляется запуск превращения действий, условий и вставок на естественном языке, в Javascript код
- Кнопка «Сгенерировать код» проверяет изменения во всём проекте и перезапускает генерацию только если что-то изменилось
- Генерированный JS код сохраняется в проекте (недоступен для редактирования)

### Полный цикл создания квеста

#### Пример: Создание простого диалога с изменением переменных

1. **Создаем структуру данных**
   - Добавляем структуру `Счет`
   - Внутри добавляем переменную `Доллары` (number) с начальным значением 0

2. **Создаем узлы**
   - Узел 1: "Вы находитесь на базе. У вас 0 долларов."
   - Узел 2: "Вы нашли сундук с деньгами!"

3. **Добавляем действие на естественном языке**
   - В Узел 2 добавляем действие: "Увеличить количество долларов на 100"
   - LLM сгенерирует JS: `variables["Счет->Доллары"] = (variables["Счет->Доллары"] || 0) + 100;`

4. **Добавляем вставку в текст**
   - В Узел 1 меняем текст на: "Вы находитесь на базе. У вас {{ показать сколько долларов у игрока }}."
   - LLM сгенерирует JS для получения строки: `return variables["Счет->Доллары"] || 0;`

5. **Добавляем условие перехода**
   - Между Узел 1 и Узел 2 создаем переход
   - В условии пишем: "У игрока есть хотя бы 50 долларов"
   - LLM сгенерирует JS: `return (variables["Счет->Доллары"] || 0) >= 50;`

6. **Генерируем код**
   - Запускаем кнопку «Сгенерировать код» на странице AI
   - Все JS коды сохраняются в проекте

7. **Запускаем игру**
   - Нажимаем F1 для выхода из редактора
   - Игра проверяет условие перехода, показывает текст с вставками и выполняет действия

#### Пример: Автоматический триггер

1. Создаем узел «Конец игры»
2. В поле `naturalLanguageTrigger` пишем: "У игрока больше 1000 долларов"
3. LLM сгенерирует JS для проверки условия
4. Когда игрок накопит 1000 долларов — он автоматически переместится в этот узел без нажатия кнопок
